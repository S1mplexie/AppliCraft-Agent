## 目录结构

```
knowledge/
├── _raw/                  五校原始调研 JSON（含完整来源清单，保留原始口径）
│   └── schema.example.json 字段规范
├── programs/<学校>/        30 份项目卡片（人读，带 frontmatter）
├── index.json             项目级索引（机器可读）
├── chunks.jsonl           RAG 分块（每行一条 JSON）
├── build.py               本库的编译脚本（改 _raw 后重跑即可）
├── query.py               不依赖向量库的本地检索 CLI
└── INDEX.md               本文件
```

## 数据纪律

1. 只采信学校官方域名（`hku.hk` / `cuhk.edu.hk` / `ust.hk` / `nus.edu.sg` / `ntu.edu.sg`）页面与官方 PDF；第三方内容仅作线索，未写入任何事实字段。
2. 学费必须带 `tuition.intake` 标签：NUS 部分项目是 AY2026/27 onwards，另一些是 AY2027/28，混用会全库数值错误。
3. 命名消歧写在 `general.notes` 与 `aliases`：例如 NUS 不存在「MSc in Artificial Intelligence」，正确名称是 `Master of Computing in Artificial Intelligence`；HKUST 无「MSc in Data Science」授课硕士。
4. 每个分块 `meta.has_unverified` 标记是否含「待核实」内容，`meta.suitable_for_writing` 标记是否适合直接喂给文书生成。

## 后续接入 RAG 的接口约定

`chunks.jsonl` 每行结构与后端 `backend/app/db/models.py` 的 `KnowledgeChunk` 表一一对应：

| chunks.jsonl 字段 | KnowledgeChunk 列 | 说明 |
| --- | --- | --- |
| `source` | `source` | 相对路径，便于回溯卡片 |
| `content` | `content` | 已自包含（块首带学校与项目名） |
| `meta` | `meta` | 学校 / 项目 / 字段 / 入学季 / 核实状态 / 是否可写作 |
| — | `embedding` | 接入时生成；表定义固定 1536 维，换模型需迁移列 |
| — | `user_id` | **本库是公共项目资料，不是用户私有材料**；接入时需用一个系统级共享账号 ID，检索条件同时带 `user_id` 与向量相似度，并过滤 `suitable_for_writing=true` |

接入建议（本轮未实现，按后续需要再做）：

1. 在 `graph/nodes.py` 的 `outline` / `draft` 节点前加检索步骤，按档案里的目标项目名召回`curriculum` / `highlights_career` / `writing_hooks` 三类分块。
2. 只把召回内容作为「项目官方表述参考」注入 Prompt，明确要求模型**不得**把其中的学费、截止日期、分数写进文书，也不得当作申请人自身经历。
3. 低置信或 `has_unverified=true` 的分块降权；生成结果里若出现具体课程名，可在事实校验节点与召回片段做一次比对。
4. 未接 RAG 前，可用 `python knowledge/query.py --school HKU --field writing_hooks` 先按关键词取参考素材，人工贴进生成面板的「补充说明」。
